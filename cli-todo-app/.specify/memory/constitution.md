# Todo Console Application Constitution

## Core Principles

### AI-Assisted Development with Human Oversight
All production code must be generated by Claude Code based on specifications. Manual code editing is allowed only for:
- Debugging and temporary diagnostic code (must be removed before merging)
- Configuration files and documentation
- Emergency fixes during critical outages (must be followed by proper specification update)
All code changes must be documented and traceable to approved specifications.

### Layered Architecture with Defined Boundaries
The application must have three distinct layers with clear interfaces:
- Data Model Layer: Contains Task class with ID, Title, Description, Status attributes
- Service Layer: Contains TodoService with methods for CRUD operations
- CLI Layer: Contains command handlers that call service methods
No direct dependencies from higher layers to lower layers are allowed. All layer boundaries must be validated through automated architecture tests.

### Specification-First Development (NON-NEGOTIABLE)
Every change must start with a spec update in the /specs folder. Claude Code should only implement features once the spec is finalized by Spec-Kit Plus. This ensures all development is intentional and well-documented.

### In-Memory Persistence
Use in-memory data structures only (Python lists, dictionaries) for task storage. No file-based or database persistence is allowed in the core application. This simplifies the architecture and focuses on business logic.

### Strict Type Hinting
Use strict Python type hinting throughout the entire codebase. All functions, methods, variables, and return types must be properly annotated to ensure code clarity and prevent type-related errors.

### Minimal Viable Implementation
Implement only the required CRUD operations for todo tasks: Add, View All (with status indicators), Update (title/description), Delete by ID, and Toggle Completion. No additional features unless explicitly specified in the requirements.

## Technical Standards

- **Python Version**: Python 3.13+ with UV package manager
- **Project Structure**: Standard /src layout managed by UV
- **Type Hinting**: Strict typing throughout with mypy validation
- **Testing**: Unit tests using pytest with minimum 80% coverage
- **Dependencies**: Minimal dependencies, prefer standard library when possible
- **Code Quality**: Follow PEP 8 standards with automated linting

## Error Handling and Security Standards

- **Error Handling**: All functions must handle expected errors gracefully and provide meaningful error messages to users
- **Input Validation**: All user inputs must be validated before processing to prevent injection and other vulnerabilities
- **Security**: Follow secure coding practices including proper input sanitization and avoiding command injection vulnerabilities
- **Performance**: CLI operations should complete within 1 second for typical usage scenarios

## Development Workflow

- **Specification Phase**: All features must be specified in /specs before implementation
- **Agentic Dev Stack**: Use Claude Code with Spec-Kit Plus for all development
- **UV Package Management**: Use UV for dependency management and virtual environments
- **Testing Protocol**: Write tests before implementation (TDD approach)
- **Code Generation**: All code must be AI-generated based on specifications
- **Quality Gates**: All code must pass type checking, linting, and tests before acceptance

## Governance

This constitution governs all development activities for the Todo Console Application. All contributors must follow these principles. Amendments require documentation of the change, approval from project maintainers, and a migration plan for existing code. All pull requests and code reviews must verify compliance with these principles before merging.
