## Summary

Implement session commands for the CLI todo app to support persistent interactive mode. The feature will add `start` and `exit` commands to allow users to enter a session where tasks persist in memory between commands. All existing functionality (add, list, update, delete, complete, incomplete) will remain available during the session with the same behavior. The solution maintains backward compatibility with existing single-command usage patterns.

## Implementation Approach

### Session Mode Architecture
The implementation will extend the existing CLI architecture to support both modes:
1. **Traditional Mode**: Current behavior where each command executes once and exits
2. **Session Mode**: New behavior where `todo start` enters interactive loop with persistent data

### Backward Compatibility Strategy
- All existing command-line arguments remain unchanged
- Service layer (`TodoService`) remains unmodified to maintain existing functionality
- CLI layer (`TodoCLI`) gets extended with session management capabilities
- Task model (`Task`) remains unchanged to preserve data integrity

### Key Implementation Elements
1. **Session State Management**: Add session state to CLI instance to track active/inactive status
2. **Command Parsing**: Extend current argparse to detect session commands (`start`, `exit`) separately
3. **Interactive Loop**: Implement command loop that persists task data between commands
4. **Error Handling**: Maintain existing error handling while adding session-specific error management
